PillCheck

Complete Project Report
Prepared September 8, 2026 · Prototype release · Repository: github.com/deepanraju448/pillcheck
Prototype and safety notice: PillCheck is a demonstration prototype, not a medical device. Medication information, OCR results, schedules, and matches must be reviewed by a qualified clinician or pharmacist. Never change medication based only on this application.

1. Project Overview

PillCheck is an accessibility-focused medication adherence prototype for people who need extra confidence when following a prescription. It combines a calm dashboard, voice controls, camera-assisted scanning, browser OCR, medicine-name matching, local adherence history, and an optional AI health-advisor proxy.

2. User Experience

  • Prototype sign-in: any valid-looking email and any non-empty password can be used for exploration. The sign-in session lasts only for the current browser tab.
  • Large-print accessibility mode and voice prompts.
  • Dashboard next-dose card based on the nearest upcoming prescribed time.
  • Medication profile for disease/problem, medicine name, treatment duration, dose times, and before/after-food instructions.
  • Morning, afternoon, and night schedules with user-selected times such as 23:10 displayed as 11:10 PM.
  • Prescription scanning entry point at the top of the dashboard.
  • Tablet, prescription, package, and receipt scan modes.
  • Read-only caregiver status view and adherence history.

3. Prescription Profile

The user can enter or review:

  1. Type of disease or problem, with voice input.
  2. Tablet or medicine name, with voice input.
  3. Number of treatment days.
  4. Morning, afternoon, and/or night dose times.
  5. Before-food or after-food instruction for each selected time.
  6. Optional dose and quantity.

Saved profile data is stored in browser local storage for the prototype. The dashboard, schedule, scan matching target, and reminder text update from the saved profile.

4. Prescription Scanning

The dashboard provides a prominent Scan prescription action. The browser camera captures a prescription image and Tesseract.js performs on-device OCR. The prototype then attempts to identify seeded medicine names, treatment duration, disease/problem labels, and time/food phrases. Recognized information is placed into the profile form for user review before saving.

For demonstrations, the prescription scanner also includes a clearly labeled Load demo prescription option. It uses a fictional seasonal-allergy sample for Cetirizine, then sends that sample through the same profile extraction path. The sample overwrites previous form values, is not a real prescription, and contains no real patient data.

OCR is a convenience feature, not a clinical extraction system. Handwriting, poor lighting, unusual abbreviations, and ambiguous instructions require manual confirmation.

5. Tablet Verification

The tablet flow starts the camera, captures a frame, runs OCR, and performs fuzzy matching against the active prescribed medicine and the local demo medicine database. It presents match, mismatch, retry, and confirmation states. Confirmed scan records are stored locally in IndexedDB.

6. Voice and Accessibility

  • Talk to PillCheck starts browser speech recognition.
  • Voice field buttons can fill disease/problem and medicine name.
  • Supported commands include scan now, confirm, repeat, remind me later, and snooze.
  • Text-to-speech reads prompts and advisor responses when supported by the browser.
  • Large-print mode increases readability and control sizing.

7. Technical Architecture

  • Frontend: HTML, CSS, and browser JavaScript in web/.
  • Local persistence: localStorage for profile/session demo state and IndexedDB for adherence records.
  • OCR: Tesseract.js loaded in the browser.
  • Server: Node static server for local development and Vercel serverless functions for deployment.
  • AI advisor: optional server-side Gemini proxy; the API key is not exposed to the browser.
  • Mobile foundation: React Native Android/iOS project remains in the repository.

8. Running Locally

Camera and microphone features require browser permission. Local development uses a simple prototype login: any email such as demo@example.com and any non-empty password such as pillcheck.

10. Current Limitations and Future Work

  • Prototype sign-in is not real account authentication.
  • Profile data is local to the current browser and is not shared between devices.
  • Prescription OCR is not reliable enough for unsupervised medical use.
  • Clinical pill identification, handwriting recognition, encrypted cloud sync, real caregiver accounts, push notifications, and clinical/regulatory validation remain future work.
  • The existing Jest baseline has a React Navigation ESM configuration issue unrelated to the web prototype changes; JavaScript syntax and browser flows were validated.

11. Responsible Use

Use PillCheck to support conversations with a clinician or caregiver, not to diagnose conditions or change medication. Confirm every medicine, dose, duration, timing, and food instruction against the original prescription.
